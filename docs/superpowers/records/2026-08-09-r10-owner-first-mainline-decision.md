# R10 owner-first 主线决策记录

日期：2026-08-09
决策者：参赛者
状态：`effective`
范围：飞书现场建设顺序、写入边界、后置验收与结果口径

## 1. 决策

暂停“必须先完成 P03 才能建设后续功能”的串行门，改为所有者身份优先落地。总控先以所有者身份、仅使用合成数据，在唯一 Base 内按最终命名、字段、关系和审计合同完成 10 张表、5 个视图、7 个 AI 节点、6 条工作流及完整合成演示链路。

本决策允许先完成所有者可见成品，但不把所有者跑通写成权限验收完成、正式上线、真实数据接入或企业效果。

2. 第 4 节旧 F0/F1 两波次及其 P01—P13 串行施工顺序。
3. 第 13 节旧 P03 prebuild gate 对后续建设的阻塞权。
4. “权限、资源命名和回滚复核完成前不得创建正式 10 表”的旧施工门。
5. “继续扩写 P04 实施规格”作为当前主线的方向；当前主线转为实际飞书落地。

未被上述覆盖的安全边界、P03 两阶段证据合同、状态真值、探针内依赖、脱敏和 R10 自动写入能力门继续有效。

## 4. 允许与禁止

允许：

- 总控以所有者身份执行最终结构的配置写。
- 在隔离目标内执行受控合成种子写和逐单元合成验证写。
- 配置全部完成后，每次只临时启用一个 AI 或工作流单元进行合成测试，并在读回或失败取证后关闭。

默认关闭或禁止：

- 连续自动业务写和未经单元隔离的自动化执行。
- 真实数据、真实客户/车辆/事故/经营数据接入。
- 外部分享、扩大协作者范围和非验收所必需的第二身份访问。
- 并行飞书写操作、一次性演示结构、把旧权限探针改名冒充正式资源。
- 把 owner run、合成结果或离线合同表述为 P03 完成、正式上线、企业业务效果或 exactly-once 已证明。

## 5. 新执行顺序

| 阶段 | 内容 | 退出条件 |
| --- | --- | --- |
| F0 | 冻结所有者身份、唯一目标 Base、`synthetic_experiment`、关闭态和回滚基线 | 分享/自动写关闭，首个空态回滚点已读回 |
| F1A | 建设 1 个 Base、10 张表、9 条关系、5 个业务视图 | 全部按最终 manifest 可见并逐单元读回 |
| F1B | 配置 7 个 AI 节点、6 条工作流 | 全部为 `configured_disabled_unverified`，无业务写入 |
| F1C | 所有者合成测试 | 每次一个单元，完成合成链路、失败降级、审计和关闭复核 |
| F1D | 后置 P03 | 真实非 owner/admin 独立会话完成两阶段隔离、撤权和重登拒绝证据 |
| F1E | 后置 CLI/OpenAPI、真实数据与最终验收 | 各项独立授权、证据和回滚门分别通过 |

F1D、F1E 不再阻塞 F1A—F1C；F1A—F1C 也不能替代 F1D、F1E。

## 6. 回滚边界

1. 总控是唯一飞书写操作方；写操作保持串行。
2. 每张表、每条关系、每个视图、每个 AI 节点和每条工作流分别形成“写前读回 → 单元写入 → 写后复核”的回滚点。
3. 失败时只关闭或回退当前单元，不删除已验证单元，不改旧权限探针，不覆盖历史证据。
4. F1C 每次只启用当前合成测试单元；完成或失败后立即关闭，确认无持续触发再进入下一单元。
5. P03 验收期间如临时开放最小分享范围，撤权、重登拒绝和分享关闭读回属于同一验收单元；未完成清理则 P03 不能完成。
