# 石听 NeoLoop｜教练沟通一页材料设计

## 目标

把赛事建议的四项会前材料要求压缩为一页，供 2026-08-10 下午与教练/企业沟通使用。阅读顺序固定为“团队是谁 → 如何理解命题 → 已经做到哪里 → 希望获得什么指导”。

## 版式

沿用现有一页企业沟通简报模板，不改变母版、字体、颜色、元素位置和信息密度：

1. 左侧：战队分工、成员擅长方向与技术栈。
2. 右上：命题理解、业务闭环和初步落地架构。
3. 右下左：当前进度，按 Demo、代码工程、飞书落地、待验收四层表达。
4. 右下右：希望教练重点指导的三类问题。

## 可见内容

### 战队分工与能力

- 刘肖蔚然：产品架构、AI/数据工作流、TypeScript/Web、工程验收与项目统筹。
- 闫紫豪：场景研究、合成数据整理、Demo 测试、内容校对与视觉表达。
- 分工继续表述为“本阶段建议分工”，不伪造成已经发生的历史贡献。

### 命题理解与落地思路

- 不重复 NeoClaw 的车辆控制和调度能力。
- 聚焦反馈进入企业后的证据关联、风险分诊、责任路由、SLA、处置回访、问题簇和改进观察。
- 目标架构保持 1 个 Base、10 张关联表、5 个视图、7 个 AI 节点、6 条工作流和两条闭环。
- 所有自动化先关闭配置，逐单元合成验收后再启用；真实数据必须经企业授权。

### 当前进度

- Demo：公开合成交互 Demo 与公开代码仓库已形成。
- 代码工程：本地核心、数据和网站测试已通过。
- 飞书落地：10 表、240 字段、9 关联、5 视图已建立；W1—W3 已保存为停用配置，W4 进行中。
- 待验收：W5—W6、逐单元合成运行、第二身份权限、审批通知、API 入口及企业字段/真实数据授权。

### 希望教练重点指导

1. 工程落地：首版最小接入集合，以及飞书原生与代码的边界。
2. 算法与验收：AI 节点、硬规则、失败回滚与企业验收标准。
3. 场景与表达：3—5 分钟主故事、Demo 重点和材料表达。

## 事实边界

- 不声称已经接入新石器真实数据或生产业务。
- 不把关闭态配置、未保存草稿或本地测试写成现场运行通过。
- 不声称自动判责、赔偿、车辆控制或最终技术根因。
- 现场数字以最近一次正式 Base 读回为准。

## 验收

- 四项通知要求均能在一页中直接定位。
- 标题和单行信息不换行，文字不溢出，不覆盖原模板元素。
- 保留讲者备注中的 60—90 秒讲法和来源块。
- 模板一致性、空占位符和页面越界检查全部通过。
