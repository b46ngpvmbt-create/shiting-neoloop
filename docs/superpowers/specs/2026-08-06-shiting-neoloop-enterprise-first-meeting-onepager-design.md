# 石听 NeoLoop｜企业首次沟通单页材料设计

- 日期：2026-08-06
- 状态：A「企业对话型」方案已获参赛者确认，等待书面规格复核
- 适用场景：石听未来与新石器企业教练的第一次小会
- 交付形式：单页 16:9 PowerPoint

> 让每条反馈都找到一辆车、一个任务、一个责任人和一次改进。

## 1. 沟通目标

这页材料不是完整路演，也不是把现有设计包装成已上线系统。它要在 60 至 90 秒内完成三件事：

1. 让企业快速判断团队是否准确理解命题边界；
2. 用可核验进度证明团队已经具备继续落地的基础；
3. 把会议转入企业最有能力回答的字段、权限、责任矩阵和验收标准问题。

成功标准是企业能够直接纠正或确认方案假设，并给出下一步落地优先级，而不是单纯认可视觉表现。

## 2. 已批准的叙事策略

采用 A「企业对话型」：团队与主责 → 命题理解和落地路径 → 当前证据 → 希望企业指导的问题。

不采用以技术名词或 Demo 为开场的方案。技术和 Demo 作为“团队已经做过什么”的证据出现，不能覆盖命题理解，也不能暗示已经接入赛事飞书或企业真实数据。

## 3. 单页信息架构

### 3.1 标题区

- 主标题：`石听未来 × 新石器｜首次沟通简报`
- 产品名：`石听 NeoLoop`
- 固定价值：`让每条反馈都找到一辆车、一个任务、一个责任人和一次改进。`
- 边界短句：`当前证据：公开资料 + 方案设计 + 合成实验；企业字段与现场能力待验证。`

### 3.2 团队建议分工

成员职责使用“本阶段建议分工”，不写成未经两人确认的历史贡献明细。

**刘肖蔚然｜队长、产品与技术总负责人**

- 主导命题拆解、产品架构、数据与 AI 工作流、Web Demo、工程验收和赛事材料；
- 方向：产品与场景设计、AI/数据工作流、TypeScript/Web/VR 可视化、项目统筹。

**闫紫豪｜场景与验证协作**

- 参与场景研究、合成数据整理、Demo 测试、内容校对和视觉表达；
- 方向：场景观察、VR/视觉表达、材料协作、测试验证。

### 3.3 命题理解与初步落地

核心判断：NeoLoop 不重复车辆控制、调度和经营问答，而是处理反馈进入企业后的协同闭环。

主路径只保留一行：

`反馈原文 → 车辆/任务/站点证据 → 人工确认责任与 SLA → 处置/回访 → 问题簇与改进观察`

落地骨架压缩为：一个 Base、十张关联表、五个视图、七个 AI 节点、六条工作流、单案与改进两条闭环。硬规则、权限和人工确认优先于 AI 建议；第一天先验收权限和字段，再决定飞书原生能力与代码辅助层的边界。

### 3.4 当前进度

只展示有磁盘或公开入口证据的进度：

- 已有公开合成交互 Demo 和公开代码仓库；
- 已形成 40 强方案文档、数据契约和约 4 分 40 秒视频脚本；
- 已有 W1–W6、N1–N7、本地工程测试及 OpenAPI 接入代码；
- 已准备赛事飞书离线配置包、权限矩阵、Day 1 探针和现场实施手册；
- 待现场验证：真实 Base 资源、权限范围、企业字段、责任矩阵、SLA 和企业数据。

精确测试数、飞书资源数和运行结果只在最终制作前重新执行或核对后填写；无法重新核验时不放数字。

### 3.5 希望企业重点指导

按优先级提出三组可回答的问题：

1. **场景与数据**：真实反馈入口有哪些；车辆、任务、站点和版本可合法读取哪些稳定字段；企业已有闭环到哪一步。
2. **工程与权限**：哪些环节适合 Base、AI 节点和自动化原生实现；哪些需要代码辅助；最小权限、审批和失败恢复怎样验收。
3. **评测与表达**：P0/P1 风险、实体关联和责任路由如何建立企业金标准；3–5 分钟 Demo 最值得突出哪条主故事和哪类故障。

## 4. 视觉设计

- 画布：16:9；单页编辑式构图，不做密集仪表盘。
- 层级：标题和固定价值形成顶部锚点；左侧突出队长与团队分工；右侧按“理解—证据—请教”形成阅读路径。
- 视觉语言：延续 NeoLoop 的海军蓝、钴蓝、薄荷绿和暖白；队长信息权重高于队员，但不使用夸张功劳排名。
- 图形：只保留一条反馈闭环路径和少量状态标识，不使用复杂架构图。
- 字号：标题不低于 50 pt，区块标题不低于 24 pt，正文不低于 16 pt。
- 证据边界：用一种克制的注释样式标出“已完成 / 代码雏形 / 待企业验证”，不使用“已上线”“已接入”“真实效果”等表述。

## 5. 演示与资料流

这页材料只读取已经存在的项目事实，不调用企业系统，也不展示凭证、内部资源 ID、未授权个人信息或合成业务明细。会议中先讲命题理解，再用 Demo 与代码作为证据，最后停在三组指导问题上。

公开事实、方案设计、合成实验和待企业验证保持四类分离。若企业当场纠正字段、流程或权限假设，会后更新项目正式规格；不在会中口头把新信息直接写成已验证结论。

## 6. 异常处理

- 公网 Demo 临时不可用：仍可用单页材料说明方案，不声称 Demo 已通过当次网络验证。
- 精确测试数无法重跑：删除数字，只保留“已有自动化测试与记录”。
- 企业指出已有同类能力：把该能力标为企业基线，收缩 NeoLoop 范围，不争辩内部现状。
- 分工被成员修正：以两名成员本人确认的口径替换“建议分工”。
- 企业时间不足：只讲固定价值、命题切入点、当前证据和第一优先问题。

## 7. 验收方法

制作完成后必须检查：

1. 四项会前要求均能在一页内定位；
2. 60 至 90 秒可以讲完，不依赖演讲者阅读小字；
3. 没有未填写占位项、文本溢出、异常换行或无意义装饰；
4. 刘肖蔚然的主导职责明确，闫紫豪的协作职责完整且不贬低；
5. “已完成、代码雏形、待企业验证”没有混写；
6. 所有精确进度数字都能回到最新测试记录；
7. 最终 PPT 每页渲染检查和越界检测通过；
8. 演讲备注中的外部资料和非平凡公开主张包含来源记录。

## 8. 非目标

- 不制作完整复赛路演稿；
- 不把一页材料扩展为项目说明书；
- 不引入未经确认的真实企业痛点、效果数字或成员经历；
- 不在本轮修改公开网站、飞书配置、工程内核或赛事提交文档。
