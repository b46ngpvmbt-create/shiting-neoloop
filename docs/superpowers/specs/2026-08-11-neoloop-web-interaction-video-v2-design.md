# 石听 NeoLoop｜飞书实操 + Web 双循环 Demo 视频 V2 设计

日期：2026-08-11  
状态：已经参赛者确认方向，实施中
队伍：石听未来  
产品：石听 NeoLoop

## 1. 目标

将已落地的真实飞书环境操作、现有 `/software` 运营工作台和本地双循环沙盘编入已有 4 分 35.8 秒 Demo 的新版本。新版必须在 5 分钟以内，让评委看到飞书 Base 与工作台中的现有合成数据、产品界面、个案闭环、改进闭环和人工退回重审，而不是只看抽象流程动画。

当前飞书口径冻结为“真实飞书环境中的合成演示版可用”：10 张表、5 个视图、工作台和 6 条工作流已经落地，当前工作流状态为 `6 条 / 0 启用 / 6 停用`，并已完成一条合成建案读回；不等于生产上线、真实企业数据接入或全链路副作用全部跑通。

旧版视频不得覆盖、重命名或就地改写。新版作为独立候选输出，只在完成验收后才增补到评委体验包。

## 2. 产物与不覆盖规则

- 保留原文件：`video/neoloop-demo/output/石听NeoLoop_4分36秒_Demo_v1.mp4`。
- 新建独立 Remotion composition：`NeoLoopFeishuWebV2`。
- 新版源文件使用独立组件，不改写 `VoiceSyncedDemo.tsx` 的 V1 故事板与时间线语义。
- 新视频最终名称按实际时长生成，形如 `石听NeoLoop_4分xx秒_飞书实操增强版_v2.mp4`。
- 开始制作前和交付后分别记录 V1 的 SHA-256，两次必须完全一致。

## 3. 创意方案

采用“原动画保留定位与证据边界，中段以飞书实操为主证据、Web 双循环为补充解释”的替换式整合。录制画面不作为右下角画中画，而是成为主视觉；传达范围、证据层和交付物时再回到原动画语言。

不直接把一段 90 秒录屏追加在片尾，也不同时堆叠动画和网页。这样可以避免时长超限、字号过小和产品交互被视为附加项。

## 4. 成片时间线

目标时长为 4 分 45 秒至 4 分 55 秒，绝对上限为 4 分 59.0 秒。

| 时间 | 主要画面 | 旁白与信息任务 |
| --- | --- | --- |
| 0:00–0:35 | V1 片头、六渠道入口、双循环定位 | 保留产品名、一句话价值和不控制车辆的范围线 |
| 0:35–1:18 | 飞书工作台总览、Base 已连接、六条工作流启用和六个模块 | 建立“真实飞书环境 + 合成数据”的落地证据，不宣称生产上线 |
| 1:18–2:25 | 飞书收件箱、案件、工单与关联字段的只读查看 | 展示渠道来源、案件关联、任务状态和责任边界；不新增、不审批、不触发通知 |
| 2:25–3:08 | 飞书问题簇、改进项目、AI 审计与流程配置状态 | 展示改进闭环、证据追溯和已启用流程；配置骨架按设计路径表述 |
| 3:08–3:55 | `/software` 本地沙盘：人工退回补证、补证重提与双循环关联 | 用 Web 界面解释飞书现场不适合演示的治理细节和失败关闭 |

| 4:22–4:52 | 体验入口、GitHub、队名、产品名和一句话价值 | 用“让每条反馈都找到一辆车、一个任务、一个责任人和一次改进”收束 |

## 5. 飞书与 Web 画面生成

飞书片段直接录制当前已登录环境，录制动作仅限页面切换、打开现有记录、展开列表、查看关联字段和返回。禁止在录制中创建、修改、审批、删除、重新授权或触发工作流。原始录屏在进入成片前裁掉浏览器账号区，并遮罩资源 ID、用户信息、OAuth/令牌和其他非公开标识。

必须录制的飞书状态：

1. 工作台显示 Base 已连接及 `6 条 / 0 启用 / 6 停用`。
2. 六个业务模块的导航和状态差异。
3. 反馈收件箱的来源、案件关联与“查看全部”。
4. 案件、工单、问题簇、改进项目和 AI 审计的现有合成记录。
5. 一条已校验的合成建案读回；该画面只表述为合成试运行。
6. Base 表、视图或流程配置的只读落地证据。

Web 片段使用 Playwright 在 1440×900 视口下读取真实本地页面状态，生成确定性关键帧。渲染期间不通过 iframe 访问网络，也不调用真实接口。

必须捕获的状态：

1. 反馈收件箱与来源列。
2. 固定证据链和案件驾驶舱。
3. 本地沙盘 0/10 初始状态。
4. 实体确认的“退回补证”表单。
5. 已退回卡片，显示原因、返回节点和下一责任角色。
6. 补证批次 R1 已重新提交。
7. 10/10 完成页，显示“本地退回 1 次”。
8. 问题地图与改进追踪。
9. 价值测算器参数修改前后。

关键帧之间由 Remotion 增加鼠标路径、点击波纹、局部 105%–115% 缩放、元素聚焦蒙版和克制的状态过渡。鼠标不得无意义来回移动，每次点击都要对应旁白中当前讲解的信息。

## 6. 旁白、字幕与音频

- 优先复用 V1 已验收的 13 段旁白音频、字幕断句和时间顺序。
- 不为 Web 操作增加无关语句；人工退回支线优先通过屏幕文案和操作节奏表达。
- 若必须补充一句退回口径，只能从已有的 15 分钟视频或已批准旁白资产中取得，不自行变更说话人或新建其他声线。
- 字幕保持 1920×1080 下不低于 36 px，不遮挡页面主操作区。
- 全片左上角固定显示“合成演示”，根据画面切换“方案设计 / 本地合成验证 / 合成假设 / 本地交付证据”标签。

## 7. 数据与证据边界

- 只使用 `SYN` 前缀对象和公开合成快照。
- Web 交互仅改变 React 内存，不保存、不发送通知、不调用飞书工作流。
- 不展示 OAuth、访问令牌、飞书资源 ID、账号信息、企业内部资料或未脱敏运行记录。
- 不把本地沙盘说成真实业务接入、生产上线、企业效率提升、AI 自动判责或最终根因确认。
- 飞书现场状态只能消费总控已冻结、已脱敏和已校验的证据。本版使用 2026-08-12 总控确认的冻结状态，并在全片保留“真实飞书环境｜合成数据”标签。

## 8. 实现边界

- 实现范围仅限新视频 composition、飞书录屏与 Web 关键帧、独立时间线、新输出、验收记录和体验包的增量更新。
- 不修改网站业务逻辑；飞书只做只读导航，不修改 Base、AI 节点、工作流、权限或现场证据。
- 不发布 Netlify，不推送 GitHub，不上传视频，不创建 Release，不执行赛事提交。
- 体验包保留 V1；增强版验收通过后，新视频作为第二个可选视频进入包内，不删除 V1。

## 9. 失败处理

- 任一飞书录屏或 Web 关键帧不存在、尺寸不一致、显示敏感信息或不符合固定对象 ID 时，停止渲染。
- 旁白时长与画面节奏冲突时，优先压缩停顿、鼠标移动和转场，不加速到影响语音可懂度。
- 成片超过 4:59.0 时视为失败，不通过修改封装元数据伪造时长。
- 字幕、音频或录屏任一项尚未验收时，新版不进入体验包清单。

## 10. 验收标准

### 10.1 视频技术验收

- MP4、1920×1080、30 fps、H.264 视频、AAC 48 kHz 双声道。
- 时长在 4:45.0–4:59.0 之间。
- 无黑帧、静音断层、帧冻结、字幕裁切、变形缩放或转场闪烁。
- 所有网页文字在最终 1080p 成片中可辨读；局部缩放不遮蔽当前操作的上下文。

### 10.2 故事与交互验收

- 评委能在不看说明文档的情况下理解来源、个案、工单、问题簇和改进项目之间的关系。
- 至少展示一次 Web 中的“退回补证 → 补证重提 → 再次确认”，并明确它是治理机制演示，不伪装成录制期间新触发的飞书操作。
- `SYN-CASE-017`、`SYN-CLUSTER-001`、`SYN-IMPROVEMENT-001` 的名称、顺序和状态与 Web、视觉附录和体验包一致。
- 价值测算修改参数后重新计算正确，并始终显示合成假设边界。

### 10.3 音画与事实验收

- 13 段旁白的字幕文本、出现时间和当前画面语义逐段核对。
- 对关键时间点输出联系表，至少检查收件箱、人工退回、改进闭环、价值测算和片尾。
- 执行禁用主张扫描，不出现“已接入新石器真实数据”、“企业效率已提升”、“AI 自动判责”、“最终根因已确认”等无证据表述。
- 复查 V1 视频 SHA-256 未变；V1 和 V2 都能独立播放。

## 11. 完成定义

只有以下产物同时存在并通过验收，才记为 V2 制作完成：

1. 独立 Remotion composition 与新时间线。
2. 全部飞书录屏、Web 关键帧与捕获清单。
3. 5 分钟内的独立 V2 MP4。
4. 视频元数据、音画同步和关键帧验收摘要。
5. 新版体验包清单与 SHA-256，同时保留 V1。
