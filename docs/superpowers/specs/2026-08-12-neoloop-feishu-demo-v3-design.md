# 石听 NeoLoop｜飞书落地演示视频 V3 设计

日期：2026-08-12  
状态：已实现并完成本地验收
队伍：石听未来  
产品：石听 NeoLoop

## 1. 目标

重做现有飞书实操增强版的音画关系。V3 不再沿用 V1 的抽象方案旁白，而是根据已经录制的飞书落地画面和 Web 双循环操作重新编写、重新合成旁白。每句话只配与其语义直接对应的界面状态，并加入全程无底字幕。

V1 与 V2 保持原文件和原校验值不变。V3 使用独立 composition、独立旁白、独立字幕 JSON 和独立输出文件。

## 2. 叙事口径

主证据是“真实飞书环境中的合成演示版”，Web 是对人工治理分支的本地交互补充，离线包是可复现工程证据。三层证据不能互相替代。

飞书当前只表述以下冻结事实：

- 一个统一 Base 承载 10 张业务表、240 个字段和 5 个业务视图。
- 工作台包含总览、接入与案件、处置与 SLA、问题与改进、AI 与审计、主数据与知识六个模块。
- 6 条工作流处于启用配置状态。
- 当前数据是合成数据；已启用不等于真实企业生产上线，也不等于所有通知、外部接口和业务副作用均已验证。

不表述为已接入新石器真实数据，不宣称企业效率已经提升，不把 AI 候选写成自动判责或最终技术根因。

## 3. 成片结构

设计上限为 4 分 59 秒。最终依据落地信息去除重复表述，成片为 2 分 53.1 秒。

| 时间 | 旁白任务 | 对应画面 |
| --- | --- | --- |
| 0:00–0:22 | 产品定位、两个闭环和范围 | 品牌片头与双循环关系图 |
| 0:22–0:52 | 飞书落地规模与当前状态 | 飞书总览、Base 已连接、10 表、5 视图、6 条启用配置 |
| 0:52–1:28 | 全渠道接入、原文留存和案件形成 | 飞书“接入与案件”，来源字段、原始反馈、反馈案件 |
| 1:28–2:06 | 实体与责任人工确认、工单和 SLA | 飞书“处置与 SLA”，案件、工单、责任与时钟字段 |
| 2:06–2:38 | 问题簇、改进项目和观察重开 | 飞书“问题与改进”，问题簇、改进项目、观察状态 |
| 2:38–3:30 | 退回补证、重提、通过和个案关闭 | Web 本地沙盘相应关键状态，严格跟随操作旁白切换 |
| 3:30–3:55 | AI、规则、人工与审计边界 | 飞书“AI 与审计”“主数据与知识”与边界提示 |
| 3:55–4:18 | 三层证据和固定故事链收束 | 飞书、Web、离线包三层证据与固定合成 ID |

允许因最终语速在各段之间移动 2–4 秒，但不得把不相关的飞书模块作为填充画面。最终实现采用 17 个语义镜头和 32 张字幕卡。

## 4. 新旁白内容

旁白使用单一、中性偏温和的专业中文女声风格。允许重新合成全部音频，不混用 V1 句段。

旁白按以下信息顺序撰写并冻结：

1. “我们是石听未来，作品是石听 NeoLoop。它让每条反馈都找到一辆车、一个任务、一个责任人和一次改进。系统包含个案闭环和改进闭环，但不执行车辆控制。”
2. “现在看到的是真实飞书环境中的合成演示版。一个统一 Base 承载十张业务表、二百四十个字段和五个业务视图；六条工作流处于启用配置状态。这里展示的是当前落地结构，不等同于真实企业生产上线。”
3. “反馈可以从 App、客服、热线转写、邮件、飞书和经授权公开平台进入。接入层保留来源、原文、接收时间和幂等键，再形成反馈案件。未配置的渠道只保留接入契约，不宣称已经接通。”
4. “案件进入分诊后，硬规则先于 AI。AI 只提出事实、风险、车辆、任务和责任候选；证据不足时必须停下。正式实体和责任由授权人员分别确认，确认后才进入工单与 SLA 协同。提醒、升级和改派都不能重置原始 SLA 起点。”
5. “单个案件关闭后仍会进入跨事件观察。相似事件保留各自记录，只关联到同一个问题簇。根因仍是假设，负责人确认后才形成改进项目，并在七天和三十天观察；复发时重新进入处置和改进。”
6. “飞书适合承载数据和确定性流程，Web 沙盘补充展示人工治理细节。这里先把实体候选退回补证，记录原因、返回节点和下一责任人；补充证据后重新提交，再分别通过实体和责任关口，创建工单、完成回访并关闭个案。随后，案件进入问题簇候选和改进立项。这个沙盘不保存数据，也不触发真实飞书工作流。”
7. “AI 审计保留输入、候选、证据和人工决定。P0、P1 硬规则优先，风险只允许上调；字段不足、权限不足或节点失败时，系统保持原状态并转人工。系统不自动判责、赔偿或确认最终技术根因。”
8. “Web 体验展示交互，飞书展示当前落地，离线包证明工程材料可复核。三层证据共同追踪 SYN-CASE-017、SYN-CLUSTER-001 和 SYN-IMPROVEMENT-001。石听 NeoLoop，让每条反馈都找到一辆车、一个任务、一个责任人和一次改进。”

为控制时长，可以删减重复修饰语，但不能删减证据边界或改变固定事实。

## 5. 音画同步规则

- 每个旁白句段拥有一个明确的 `sceneId`、开始时间、结束时间和唯一主要画面。
- 画面切换以句段开始为锚点，允许提前 4–8 帧进入，不允许在句段结束后继续停留于下一句无关界面。
- 讲到“10 张表、240 个字段、5 个视图、6 条工作流”时只显示飞书总览状态。
- 讲到接入、案件、工单、问题簇、改进项目、AI 审计时，分别显示对应模块，不使用连续录屏自然播放替代语义剪辑。
- Web 的“退回补证 → 补证重提 → 实体通过 → 责任通过 → 建单 → 关闭 → 聚类 → 改进立项”按旁白动作逐步切换关键状态。
- 无可对应的真实录屏时回到原动画或使用已验收截图，不用错误模块填充。

## 6. 无底字幕

- 字幕数据使用 Remotion `Caption` JSON：`text`、`startMs`、`endMs`、`timestampMs`、`confidence`。
- 字幕与新旁白使用同一分段时间源，避免手工维护两套时序。
- 居中放在下方安全区，最多两行；单行优先，每页建议 13–22 个汉字。
- 字号 42 px，字重 700，白色文字，4 px 黑色描边，轻微黑色阴影；不使用任何底色、色块、磨砂层或胶囊背景。
- 字幕不得遮挡当前操作按钮、核心状态和表格关键字段；必要时可在安全区内上移，但同一场景位置保持稳定。
- 句间停顿时字幕消失，不长期残留上一句。

## 7. 实现方案

- 新建 `NeoLoopFeishuWebV3` composition，不修改 V1/V2 composition 的行为。
- 新建 V3 旁白脚本、分段音频、Caption JSON 和语义镜头映射。
- 复用已有飞书只读录屏、Web 关键状态截图与原动画组件，不重新操作飞书业务数据。
- 若现有飞书录屏没有足够清晰的对应画面，只裁切、定格、缩放或使用现有截图，不执行新增、编辑、审批、删除和工作流触发。
- 最终文件命名为 `石听NeoLoop_飞书落地演示_无底字幕_v3.mp4`。
- 不发布 Netlify、不推送 GitHub、不上传视频、不创建 Release、不提交赛事系统。

## 8. 验收标准

- MP4、1920×1080、30 fps、H.264、AAC 48 kHz 双声道，时长不超过 4 分 59 秒。
- V1、V2 的 SHA-256 在制作前后保持一致。
- 对全部旁白句段逐项验收“听到的对象、看到的模块、字幕文字”三者一致。
- 字幕全程无底色，无裁切、无遮挡、无超过两行；关键时间点截图可读。
- 无 0.5 秒以上黑场，无 2 秒以上异常静音，无音频重叠、突变或重复句。
- 禁用主张扫描通过；全片固定区分真实飞书环境、合成数据、Web 本地沙盘和离线证据。
- 通过后作为独立 V3 加入体验包，V1/V2 均保留。

## 9. 完成定义

只有 V3 源码、旁白、Caption JSON、成片、音画对照验收记录、技术验收和更新后的体验包同时存在，才记为完成。

## 10. V4 无遮挡修订

- 保留 V1—V3，另建 V4 候选。
- 所有镜头取消全屏暗层、底部渐变和左下大标题说明，页面使用原始亮度与饱和度。
- 仅保留左上角小型来源标签，以及底部居中的无背景字幕。
- 字幕保持 42 px 白字，将黑色描边加强到 6 px，并叠加轮廓阴影；可读性不依赖遮挡页面的色块。
- 旁白、字幕内容、时间轴和镜头顺序不改变。
