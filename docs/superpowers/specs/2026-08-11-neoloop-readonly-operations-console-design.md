# 石听 NeoLoop｜只读运营工作台设计

日期：2026-08-11  
状态：依据已批准的自由展示区软件扩展授权进入实施  
入口：`/software`

## 1. 目标

把现有展示型首页补充为更像企业软件的 90 秒可操作工作台。评委可以从反馈收件箱进入案件、工单、问题簇和改进项目，查看同一条合成故事链中的关系、证据状态和人工关口。

固定故事链：

`SYN-CASE-017 → SYN-CLUSTER-001 → SYN-IMPROVEMENT-001`

工作台只读取公开合成快照；操作仅改变浏览器内的筛选、选择和面板状态，不创建记录、不发送消息、不控制车辆、不触发飞书或任何外部工作流。

## 2. 方案比较

### A. 独立只读运营工作台（采用）

- 保留现有首页作为方案叙事和自由展示区。
- 新增 `/software`，使用应用壳、模块导航、数据区和证据检查器。
- 优点：软件感明确，评委能快速操作；不破坏首页结构；继续复用唯一公开数据源。
- 代价：需要为新路由增加导航、响应式和浏览器验收。

### B. 继续加深首页五视图

- 优点：改动较小。
- 缺点：首页已经承担叙事、双循环、价值测算和证据边界，继续叠加会降低软件感和可发现性。

### C. 新建桌面应用或 PWA

- 优点：包装感更强。
- 缺点：需要安装或权限解释，与赛事快速体验不匹配，也会形成第三套交付链。

## 3. 信息架构

工作台包含五个模块：

1. 反馈接入：展示授权渠道、原始反馈、进入方式与关联状态。
2. 个案闭环：展示案件、风险、候选实体、人工关口与关联工单。
3. SLA 协同：展示责任候选、到期时间、升级级别和原时钟边界。
4. 问题地图：展示跨事件问题簇、成员案件、假设和反证边界。
5. 改进观察：展示改进项目、7/30 天观察窗、指标口径和人工结论状态。

全局应用壳包含：

- 顶栏：产品、只读边界、返回展示页。
- 左侧导航：五模块与固定故事链快捷入口。
- 中央区：搜索、状态筛选、记录列表或关系卡。
- 右侧检查器：当前记录 ID、证据类别、关系、人工关口和允许/禁止动作。
- 导览模式：按固定故事链依次选中案件、问题簇和改进项目。

## 4. 状态与数据流

- 唯一数据来源为 `app/public-snapshot.ts` 派生的公开快照。
- URL 路由只区分 `/` 与 `/software`；工作台内部状态不写服务端。
- 搜索和筛选在客户端进行；无结果时显示可恢复空状态。
- 选择记录只更新右侧检查器；刷新后回到默认固定故事入口。
- 所有关键按钮使用动词“查看、筛选、导览、返回”，避免“创建、派单、发布”等真实写入暗示。

## 5. 视觉与响应式

- 延续现有暖纸色、深墨绿、石听荧光绿和编辑部式排版。
- 工作台比首页更紧凑，采用细分隔线、数字索引和表格式密度，不使用大面积玻璃、发光或悬浮阴影。
- 桌面端为左导航 / 主区 / 右检查器三栏。
- 平板收窄右检查器；手机端将导航变为横向模块栏，检查器落到列表下方。
- 焦点轮廓始终可见；按钮和记录行全部支持键盘操作；减少动态模式下取消位移动画。

## 6. 内容与证据契约

- 所有业务记录标记为合成样例或历史合成快照。
- 飞书现场状态不从本地材料推断；固定写“由总控冻结并单独验收”。
- AI 只表述为候选、证据和草稿，不表述为自动判责或最终根因确认。
- 价值和 SLA 均不表述为企业真实成效。
- 页面不新增个人信息、OAuth、资源 ID、令牌或内部路径。

## 7. 验收

- 五模块可切换，搜索、筛选、记录选择、空状态恢复和固定故事导览可用。
- 案件、问题簇和改进项目的 ID 关系一致。
- 桌面 1440×900、移动 390×844 无横向溢出；键盘焦点与控件名称明确。
- 控制台无错误，第一方资源无失败；根页面和 `/software` 均完成生产构建。
- 禁用主张、隐私与敏感信息扫描通过。
- 不执行 Netlify 发布、GitHub 推送或赛事提交，除非用户另行明确授权。
