# 石听 NeoLoop｜人工关口退回与重审设计

日期：2026-08-11  
状态：用户确认“加入”  
范围：`/software` 本地沙盘

## 1. 目标与边界

现有人工关口只能确认通过，无法表达企业流程中常见的证据不足、候选错误和重新提交。本变更为 4 个人工关口增加：

- `确认通过`；
- `退回补证`；
- `驳回候选`；
- 必填原因；
- 退回节点和下一责任角色；
- `模拟补证并重新提交`；
- 重审后再次确认或退回。

全部动作仅修改 React 内存状态，刷新即清空。不写入飞书，不发送通知，不伪造审批人、时间戳或企业运行日志。

## 2. 方案选择

### A. 为退回新增 4 个主流程步骤

流程图会更细，但主链从 10 步扩张为 14 步，直线通过时出现无意义的空节点。

### B. 人工关口内的审查支线（采用）

保留 10 步主链。用户选择退回或驳回后，当前关口切换为“已退回”状态，展示原因、目标节点和责任角色。模拟补证后返回同一关口重审。这能同时表达失败关闭和恢复路径，又不破坏既有双循环主链。

### C. 只增加一个“打回”按钮

开发量最小，但没有原因、去向、责任人和恢复路径，仍然不是完整人工关口。

## 3. 四个关口的返回契约

| 人工关口 | 退回补证的目标 | 驳回候选的目标 | 下一责任角色 |
| --- | --- | --- | --- |
| 实体确认 | 实体证据补全 | 实体候选重新生成 | 数据校验角色 |
| 责任确认 | 责任路由依据补全 | 责任候选重新生成 | 路由管理角色 |
| 回访关闭 | 处置证据或回访记录补全 | 结案候选撤销并继续处理 | 工单处理角色 |
| 改进立项 | 问题簇证据与反证补全 | 立项候选撤销并重新评估 | 问题管理角色 |

“退回补证”表示方向可能正确但证据不足；“驳回候选”表示当前候选不应进入下一节点。两者在文案、状态标签和返回目标上明确区分。

## 4. 交互状态

人工关口的本地状态为：

`pending → composing_return → returned → resubmitted → approved`

另一条直达路径为：

`pending → approved`

行为规则：

1. 点击“退回补证”或“驳回候选”后打开当前卡片内表单。
2. 原因为必填项；空值不能提交，失焦或尝试提交后显示可读错误。
3. 用户可取消退回，恢复待审状态。
4. 提交后显示审查类型、原因、返回节点和下一责任角色。
5. 点击“模拟补证并重新提交”后，证据区增加“补证批次 R1”，关口回到可审查状态。
6. 重审通过后进入下一主步骤，但“本地退回 1 次”保留在审查记录中。
7. 重置沙盘或刷新页面后，退回记录与原因一起清空。

## 5. 数据结构

不修改 canonical 数据。审查结果是页面内的合成演示状态：

```ts
type LocalReviewEvent = {
  gateKey: string;
  gateLabel: string;
  decision: "return_for_evidence" | "reject_candidate" | "resubmitted" | "approved";
  reason: string;
  returnTarget: string;
  nextOwnerRole: string;
  iteration: number;
};
```

不记录真实审批人、账号、系统时间或外部记录 ID。

## 6. 视觉与可访问性

- 确认通过使用深绿主按钮。
- 退回补证使用黄棕轮廓按钮。
- 驳回候选使用中性深灰轮廓按钮，不使用大面积危险红色。
- 退回表单在当前卡片内展开，不额外叠加模态框。
- 错误文案使用 `role="alert"`；表单控件有可见标签、字数提示和焦点轮廓。
- 退回完成后将焦点移到“模拟补证并重新提交”；重新提交后将焦点返回“确认通过”。

## 7. 验收

- 4 个人工关口均提供三种决策。
- 原因为空时不能提交，并显示可读错误。
- 退回补证和驳回候选的状态、去向和责任角色不同。
- 可完整操作“实体确认 → 退回补证 → 补证重提 → 重审通过”。
- 也可使用直线通过路径完成 10/10 步。
- 完成摘要显示本地退回次数；重置后次数归零。
- 不出现网络写请求、`localStorage` 或 canonical 数据变更。
- 桌面端和手机端无横向溢出，控制台无错误。
- Node 22.13.0 下 lint、渲染测试、公开数据边界、生产构建和双路由静态导出通过。
- 不部署、不推送、不修改飞书。
