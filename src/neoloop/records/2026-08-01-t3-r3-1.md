## 完成内容与代码证据

### 1. 运行时命令边界与裁剪安全审计

- `src/neoloop/workflows/w3.ts` 在访问事件仓前验证 `workflow=W3`、非空 `event_id/case_id`、闭集 action、action 专属字段、duplicate decision、人工 actor 与 formal entity 的 plain own-data shape。
- exact own-key 检查拒绝继承字段、异常 prototype、额外字段、symbol 字段和 accessor 字段；authorizer decision/principal 同样要求可信 plain record。
- 反射、getter 或 Proxy trap 异常统一降级为 `invalid_command / unsafe_object_shape`，不再让 `runW3` reject。
- 非法命令只用安全提取的 own data 引用或固定回退值写一条裁剪后的 security audit；不记录完整命令、actor、异常消息或秘密。即使 audit port 失败，仍 fail-closed，且事件仓、授权器、AI、领域仓访问均为 0。

### 2. 可信人工授权与可举证决策

- `resolve_same_event`、`confirm_formal_entity`、`confirm_routing` 均调用外部 synthetic allowlist authorizer；命令自报的 `is_human`、actor role 或 case-only permission 不能构成授权。
- authorizer 返回规范化 principal、policy version 和授权决定；仓储写入口消费一次性 opaque capability，并把稳定 `decision_id`、principal、action、authorization state、proposal/rule reference 与 `decided_at` 保存到事件结果和 workflow audit。
- 授权目标精确绑定 action/case，并按动作绑定 check/candidate/fingerprint、entity proposal/formal entity，或 routing proposal/rule/team/role/SLA。
- 拒绝、授权器异常、伪 role、继承 principal、目标权限不足和 capability 重放均 fail-closed；同 event 重放复用原 decision，不重新调用授权器。

### 3. W6 same-event 不可变绑定

- same-event check 进入 W3 前必须具有 repository-private receipt；字段形状合法但直接写入 public fixture Map 的 check/resolution 不再被视为可信提交。
- `keep_separate` 授权目标同时绑定 `check_id`、`candidate_case_id` 和完整 `check_fingerprint`；authorizer 调用期间把候选 A 替换为 B 会在提交前复检失败，N4 调用为 0。
- resolution receipt 复合绑定人工决策与所引用 check；重放只复用同一个已提交 decision。

### 4. AI envelope、proposal 与读取路径二次校验

- W3 使用现有唯一真源 `validateNodeRequestDefinition`、`validateAiNodeEnvelope`、`validateNodeCandidate`、`createAiInputHash` 和 `AI_NODE_DEFINITIONS.N4/N6_RESPONSIBILITY_ROUTING`。
- 保存 N4/N6 proposal 前精确比较 node/mode/version/object_ref/input_hash；候选、evidence span、support/counter 与当前合成 reference bundle/routing rule set 全部重新绑定。
- repository 依据持久化输入重建相同 request 并校验 exact hash；跨 case envelope、伪 node/mode/version/hash、越界证据和非输入候选均不得落盘。
- proposal、formal decision、routing decision、dispatch snapshot 的读取和幂等返回都消费 private verified fingerprint；完整形状的 public Map 直写、部分导入、缺 receipt、引用漂移和损坏快照均返回明确 invariant failure，不能伪装为 idempotent。
- receipt 校验与提交使用 ECMAScript `#private` 同步临界段，不再 `await` 可覆写的 public verifier，关闭 check-after-mutate TOCTOU。

### 5. 事件重放、锁与审计后提交语义

- 同 event 正在执行时重入会显式失败，不再等待自己的 promise；活动 case/audit owner 的 ALS 继承重入（含 detached child 和外部 port）同样失败关闭，stale owner 仍正常排队。
- 同 event 重放始终标记 `event_replayed=true`；原结果为 `failed` 或 `needs_human` 时保留原 status，只有已完成结果转为 `idempotent`。重放不重复授权、AI、人工决策或领域副作用。
- 事件结果先缓存、首次 workflow audit append 后失败时，返回稳定 `audit_pending` / `audit_failure_after_commit` 语义；不释放幂等键、不谎称原状态未变。重放只补审计或稳定呈现 pending，不重复业务效果。
- 不同 event 对同 case 的 `advance` 使用 per-case single-flight：未关联阶段 N4 只调用一次；实体确认后 N6 只调用一次。第二个事件复用同一人工 gate，但不会被错误标记成同 event replay。

### 6. 派单不变量、SLA 与 W4 兼容

- `confirm_routing` 要求 `formal_entity_confirmation_status=已人工确认`、`workflow_readiness=awaiting_routing_confirmation`、完整 synthetic boundary、可信 routing decision 与版本化 synthetic SLA policy。
- `first_response_target_minutes` 必须是 `Number.isSafeInteger`、正数、不超过合成上限，并精确等于候选所引用 SLA 规则；真实 SLA 仍标为待企业验证。
- 已为待派单/处理中但缺 work order、work-order index 与 case 不一致、部分写入或损坏 order 都返回 `invariant_violation`，不合成未持久化快照，不返回 `idempotent + null`。
- 同 case 不同 event 的冲突 routing decision 通过原子冲突检测关闭；相同已提交决策可幂等，候选/团队/SLA/人工决定不同则返回明确冲突且不覆盖首个决定。
- dispatch receipt 只覆盖 W3 不可变提交材料，不覆盖 W4 合法可变的 status、accepted_at、team、role、updated_at 与 escalation 字段。
- 集成回归使用同一内存仓执行 W3 dispatch → W4 accept → W4 reassign → W3 advance/replay/confirm：返回当前改派后的 team/role，SLA 三字段不变，N4/N6、工单和 routing decision 均不重复。W4 实现未修改。
