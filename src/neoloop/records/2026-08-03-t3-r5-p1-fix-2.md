## 最小实现

### Active intake Day-7 截止

- 在 N5 active-intake validation receipt 签发和最终 transition commit 两个权威边界使用同一条件：
  - `intake.occurred_at > day7_expected_at`；且
  - `trigger.closed_at <= day7_expected_at`；
  - 满足时失败关闭。
- 判定不再依赖 Day-7 checkpoint 是否存在，避免通过“尚未写 checkpoint”补收旧案。
- `occurred_at == day7_expected_at` 不被该条件误伤；与 checkpoint 的并发仍由既有全资源锁和不可变 checkpoint 语义决定。

### 新 checkpoint 时间单调性

- commit 先查询相同 cycle/horizon 的现有 checkpoint：
  - 同语义直接返回原 checkpoint 与原 receipt；
  - 任一语义字段不同立即报 immutable conflict。
- 只有 checkpoint 尚不存在时，才比较 `occurred_at` 与 repository-authoritative `cluster.updated_at`、`improvement.updated_at` 的最大值。
- `occurred_at` 早于该最大值时失败关闭；相等允许。该守卫位于 CAS 和业务写入前。
