# 石听 NeoLoop｜第一天权限验收矩阵

日期：2026-08-01  
版本：T2-R3-draft  
事实类别：方案设计  
当前结论：所有赛事飞书能力均为“未测试”

本矩阵只定义获得赛事账号后的实测动作，不表示已经获得任何权限、创建了真实 Base，或接入了新石器数据。测试仅使用醒目标记的合成样例。

## 1. 执行状态、能力结果与派生状态

机器记录必须同时遵守以下真值表；`execution_status` 表示执行进度，`result` 只表示已完成后的能力裁决：

| `execution_status` | `result` | `evidence` | 派生中文 / 英文 | 判定规则 |
| --- | --- | --- | --- | --- |
| `not_tested` | `null` | `null` | 未测试 / `not_tested` | 尚未开始，或登录、第二账号、OAuth、管理员审批、赛事规则等前置条件不足 |
| `blocked` | `null` | 非空且结构合法 | 已阻塞 / `blocked` | 已实际尝试，但动作、边界复验、清理或裁决材料尚未完成；不得伪装成能力结论 |
| `completed` | `可用` | 非空且结构合法 | 可用 / `available` | 正向动作、权限边界动作和复验均通过，且没有影响目标用途的限制 |
| `completed` | `受限` | 非空且结构合法 | 受限 / `restricted` | 能完成部分目标，限制和保底路径均已实测 |
| `completed` | `不可用` | 非空且结构合法 | 不可用 / `unavailable` | 前置条件满足后，目标用途被明确阻止，并有完整错误或拒绝证据 |

`completed + 未测试`、`completed + null`、`completed + {}`、`blocked + 非空 result` 均为非法记录。不能因“看见入口”“文档说支持”“其他租户可用”而填写“可用”；缺少审批且尚未实际完成裁决时不是“不可用”。

P01 的精确转换规则：前置条件不足或规定动作尚未开始时只能是 `not_tested/null/null`；一旦已经尝试分享、无痕首屏或刷新中的任一规定动作，而动作、复验或证据仍不完整，则只能是 `blocked/null/非空脱敏结构化证据`。

## 2. 第一轮基线矩阵

严格顺序为 P01→P02→P03；P01 与 P03 证据独立，P02 未完成不得进入 P03，P03 预建门单独通过不得形成 P03 最终结果。能力名称以本表及 probe suite 为权威，尤其是 P02“Base 基础能力”、P03“Base 无特权权限”、P04“飞书 AI / Base AI”、P05“自动化 / 工作流”、P11“企业自建应用”。

| 编号 | 能力 | 当前状态 | 最小测试动作 | 通过证据 | 受限/失败证据 | D0/D1/D2 保底路径 | 必须本人或管理员参与 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| P01 | 文档匿名权限 | 未测试 | 新建临时文档，设置“互联网获得链接可阅读”，复制链接到未登录无痕窗口并刷新复验 | 分享设置截图；无痕首屏与刷新后可读截图；时间与测试人 | 已尝试但分享、无痕首屏、刷新复验或证据不完整时记 `blocked/null` 并保留非空脱敏证据；完整复验后再裁决限制或拒绝 | 保留飞书文档为登录入口；另用已匿名验收的公开站和视频承载公开体验，并在提交说明写明限制；此路径不替代最终 D0 匿名文档验收 | 参赛者本人登录并切换分享；管理员可能需开放外链策略 |
| P02 | Base 基础能力 | 未测试 | 在临时合成测试 Base 验证数据表、字段、关联、公式、视图、表单与一条测试自动化 | 每项创建或运行证据；测试后清理记录 | 缺少入口、字段类型或运行权限；配额提示 | 按能力降级为普通字段、人工状态更新与五个 Base 视图；不改变数据契约 | 参赛者本人创建临时 Base；部分租户设置需管理员 |

## 3. 记录字段

实际执行时，`blocked` 或 `completed` 行必须补齐以下字段；`not_tested` 行的 `result/evidence` 必须保持 `null`：

| 字段 | 填写要求 |
| --- | --- |
| 测试时间 | 带时区的完整时间 |
| 测试账号逻辑角色 | 所有者、管理者、普通协作者、无特权测试账号或未登录；不记录账号秘密 |
| 前置条件 | 租户、产品入口、赛事规则、管理员审批、第二账号、OAuth 是否满足 |
| 测试动作 | 实际点击、输入和复验动作；使用合成数据 |
| 预期结果 | 对照本矩阵的最小通过条件 |
| 实际结果 | 原样记录成功、限制或错误分类，不推断企业政策 |
| `execution_status` | 仅 `not_tested`、`blocked`、`completed` |
| `result` | 仅 `completed` 时填写可用、受限或不可用；其他执行状态必须为 `null` |
| 限制 | 配额、角色、租户、范围、延迟、分享或审核限制 |
| 结构化证据索引 | 权限结果的 `evidence_index` 是唯一规范源；同记录 `evidence` 和同编号现场单元 `structured_evidence_index` 必须与其 canonical deep-equal。`blocked/completed` 时必须非空；每项只登记 `evidence_id`、带时区时间、逻辑角色、受控槽位、采集阶段和 `redaction_checked=true`，不得提交敏感链接、凭证、真实资源 ID 或完整地址。`capture_phases` 完整闭集为 `before_action`、`after_boundary`、`failure`、`prebuild_gate`、`postbuild_five_view_direct_table_recheck`，非 P03 证据只能使用前三项。P03 阶段 `indexes` 必须与父 P03 索引中 `capture_phases` 包含该阶段键的完整对象过滤结果做同序 canonical deep-equal，且阶段内 `evidence_id` 唯一；不得只对比 ID、遗漏、重复或重排。阶段 `r10_subchecks` 恒为 `null`，不得成为独立第四套真值。 |
| 保底路径 | 记录所选路径、验证状态和实际结果；受限/不可用必须有已实测保底，未完成时不得伪造验证 |
| 复验人 | 至少记录执行人；关键匿名/无特权访问建议由另一人复验 |

## 4. 能力依赖门

```text
赛事规则确认
├─ 文档匿名权限（独立测试）
├─ Base 基础能力 → Base 无特权权限（prebuild gate → postbuild five-view/direct-table recheck）
├─ Base AI → 七节点现场配置
├─ Base 基础能力 + 自动化/工作流 → 审批、提醒、异常通知（P06/P07）
├─ 知识库 → N7 审核引用
├─ 妙搭（D1，可降级）
├─ Aily（D2，可省略）
└─ 企业自建应用 + 管理员批准
   ├─ Base OpenAPI
   └─ 经赛事允许和本人同意后安装/登录 lark-cli
```

文档匿名权限和 Base 无特权权限必须分别测试；其中一项通过不能替代另一项。企业自建应用未通过时，OpenAPI 和需要该应用的 CLI 调用保持“未测试”，不能标成“不可用”或“可用”。

保底路径用于继续准备和演示降级，不等于对应最终验收门已通过。P01、P02、P03 或七节点/六工作流所需核心能力若没有实际运行证据，主控仍需把相关 D0 项判为未完成。
