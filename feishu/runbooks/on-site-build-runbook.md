# 石听 NeoLoop｜现场逐屏人工搭建运行手册

日期：2026-08-01  
版本：T2-R2-offline-draft  
事实类别：方案设计  
现场状态：未执行；P01—P13 全部未测试

本手册把逻辑 manifest 转成可逐屏执行的现场动作，但不表示任何飞书资源已经创建、配置、授权或验收。所有动作只在参赛者本人完成登录并取得对应权限证据后执行；本轮不登录、不创建真实 Base、不打开 OAuth、不调用 OpenAPI、不安装 `lark-cli`。

唯一字段契约是 `../manifests/neoloop-logical-manifest.v0.1.json`。`../manifests/on-site-build-package.v0.1.json` 只规定搭建顺序、保护层、视图行为和停点；字段类型、必填、枚举、关系与人工确认属性必须在执行时从唯一逻辑 manifest 解析，不得现场凭同义名称补字段。

## 1. 现场记录约定

### 1.1 状态与证据号

- 能力执行状态使用两层合同：规定动作未开始为 `not_tested/null`；一旦已尝试但未形成最终结果为 `blocked/null`；证据完整并完成裁决后才为 `completed`，其 `result` 只能是“可用 / 受限 / 不可用”。没有规定动作和复验证据时保持“未测试”，已经尝试的单元不得回写为“未测试”。
- 搭建单元在现场证据模板中初始均为“未测试”，不能因看到入口或完成离线设计而预填通过。
- 现场证据号格式：`T2-EV-{单元}-{YYYYMMDD-HHmm}-{序号}`。例如格式示意 `T2-EV-T01-<YYYYMMDD-HHmm>-01`；尖括号内容必须由现场实际时间替换，示意本身不是证据。
- 屏幕步骤号格式：`S-{单元}-{序号}`；回退动作号格式：`T2-RB-{范围}-{序号}`。
- 证据只登记脱敏索引。完整 Base 地址、文档链接、授权 URL、设备码、token、成员联系方式和真实资源 ID 不进入仓库。
- 表证据号固定按 canonical 顺序：T01 `raw_feedback`、T02 `cases`、T03 `work_orders`、T04 `clusters`、T05 `improvements`、T06 `vehicles`、T07 `delivery_tasks`、T08 `routing_matrix`、T09 `knowledge_index`、T10 `ai_audit`；现场建表顺序不同也不得改号。

### 1.2 失败分类

| 代码 | 分类 | 停点原则 |
| --- | --- | --- |
| F01 | 入口或产品缺失 | 当前单元尚未开始时为 `not_tested/null`；已尝试但尚未形成完整结论时为 `blocked/null` 并绑定非空脱敏证据；若入口缺失已被完整观察、复验并形成拒绝证据，可裁决为 `completed/不可用`。仅下游依赖单元继续 `not_tested/null`，不猜租户能力 |
| F02 | 本人登录、OAuth 或管理员审批待办 | 当前单元未尝试时为 `not_tested/null`；当前单元已尝试但尚未形成完整结论时为 `blocked/null` 并绑定非空脱敏证据。停止后续依赖；只有未开始的下游依赖单元继续 `not_tested/null` |

| F12 | 幂等、关系或数据完整性异常 | 禁止覆盖旧记录；保留冲突与输入哈希，转人工 |

### 1.3 实际资源映射的本地隔离

仓库只保留 `../config/resource-mapping.example.json`，其中所有资源值必须为 `null`。现场产生的映射只能存为以下任一路径，且不得提交：

```text
feishu/config/resource-mapping.local.json
feishu/.local/
```

现场执行时不要修改仓库 `.gitignore`；主控已在其中预置以下两条本地隔离规则。现场负责人仍必须先用 `git check-ignore -q` 验证；若规则被删除，可临时写入本机 `.git/info/exclude`，或把真实映射存到仓库之外的受控目录。

```text
/feishu/config/*.local.json
/feishu/.local/
```

写入后必须先运行资源占位校验，再用 `git status --short -- feishu/` 确认本地映射没有进入待提交清单。若无法保证隔离，停止记录真实 ID，分类 F11。

## 2. 从 P01—P13 进入分支

通用分支规则：

- 未测试：不进入依赖搭建，只保留离线包和待办。
- 已阻塞：规定动作已经尝试但最终结果尚未形成；保持 `blocked/null`、绑定非空脱敏证据，并停在当前依赖门。
- 可用：按证据确认的范围执行对应屏幕步骤。
- 受限：先把限制和已验证保底路径写入证据；不得把部分能力写成完整通过。
- 不可用：执行已验证保底路径；若该能力是 D0 完成门，则 D0 保持未完成。

### N6 根因模式的受控目录与人工门

以下步骤是现场具备 P04 后的配置方法，不表示节点已经配置、上线或接入企业数据：

1. 调用方先从已审核的合成测试词项或企业授权词表构建 `hypothesis_catalog`。每项只含 `hypothesis_id`、`factor_label`、`phenomenon_label` 和 `uncertainty_options`；假设 ID 在本次请求内唯一，不确定项 ID 在整个目录内全局唯一。
2. 目录标签只描述因素、现象和不确定项，不写因果结论、最终根因或工作流指令。责任路由仍按 `N6-responsibility-routing-1.0.0-draft.2` 的原输入调用；根因模式按 `N6-root-cause-1.0.0-draft.3` 提交 `evidence`、`issue_cluster`、`resolution_records` 和 `hypothesis_catalog`，两种输入不得混用。
3. 根因候选的 `hypothesis_id` 和 `uncertainty_ids` 必须回指目录；`statement` 必须由目录中的因素与现象确定性生成。自由生成的新 ID、新标签或改写后的因果陈述一律校验失败并停链转人工。
4. 问题负责人同时检查支持证据、反证和不确定项。`human_review_required` 必须为真，`final_root_cause` 必须为假；审核只决定是否保留假设或进入后续改进评估，最终技术根因仍由授权人员确认。

只有以下项目都有实际证据时，才能把对应单元从“未测试”改为现场结果：

1. P01—P13 每项记录实际动作、时间、执行人、平台账号角色、实际结果、限制、证据索引、脱敏状态和复验人。
2. 十表字段顺序/类型/必填/枚举/关系与唯一逻辑 manifest 一致；没有同义别名或额外 helper 字段。
3. 五视图通过 host table、筛选、排序、可见字段、允许/拒绝动作和空态检查。
4. 三逻辑角色仍标注为逻辑分组；任何真实平台角色映射都有 P03 证据而非推断。
5. 七节点各有 envelope、一次修正重试、人工降级、禁止动作和 AI 审计证据。
6. 六工作流按严格顺序各有触发、前置状态、确定性动作、人工确认、错误停点、审计和回退证据。
7. 失败或清理没有删除正式证据，没有重置 SLA 起点，没有扩大权限绕过。

未满足的单元保持“未测试”或按实测限制记录；离线包完成不等于赛事飞书已经搭好。
