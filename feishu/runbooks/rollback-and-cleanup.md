# 石听 NeoLoop｜现场回退与安全清理手册

日期：2026-08-01  
版本：T2-R2-offline-draft  
事实类别：方案设计  
执行状态：未执行

本手册只规定未来现场失败时的回退和清理动作，不表示已经创建、停用、撤权或删除任何飞书资源。P01—P13 当前均为“未测试”。实际操作必须由赛事账号持有人在明确资源清单上执行；OAuth、凭证和管理员授权由参赛者本人及管理员处理。

## 1. 不可破坏的现场原则

1. 先停触发，再记录失败前状态，最后清理明确的临时资源。
2. 永远保留原始反馈原文、幂等键、授权范围、失败前业务状态、`sla_started_at`、AI 实际 envelope、自动化运行日志和人工决定。
3. 不把回退写成成功，不扩大权限，不用新的宽权限账号绕过原失败，不用妙搭/Aily/OpenAPI/`lark-cli` 绕过 D0 权限门。
4. 不删除正式证据、正式审计、历史状态或错误运行记录；回退本身也要有证据索引。
5. 只处理本轮明确列出的临时自动化、临时授权和带 `SYN-PERMISSION-TEST` 标记的临时记录；禁止按整表、整个 Base、“全部记录”或通配条件清理。
6. 无法确认资源归属、前状态或影响范围时立即停止，交给参赛者本人/管理员裁决。
7. 车辆与配送任务保持只读快照；回退过程不执行车辆控制、发车、调度、自动判责或企业任务状态写入。

## 2. 回退总流程 T2-RB-00—07

| 编号 | 执行主体 | 动作 | 必须保留 | 最小完成证据 | 停止条件 |
| --- | --- | --- | --- | --- | --- |
| T2-RB-00 | Base 所有者或经授权管理员 | 关闭本轮临时输入入口，停用本轮临时自动化触发；不动正式链 | 当前页面、触发器名称、资源归属、停用时间 | 停用前后截图索引和执行人 | 无法区分临时/正式自动化即停止 |
| T2-RB-01 | 执行人 + 复验人 | 记录失败对象、前状态、当前状态、`sla_started_at`、幂等键/对象引用、AI 重试次数和运行日志索引 | 原状态、SLA 起点、审计 | 一份脱敏回退清单 | 任一关键字段未知即不继续清理 |
| T2-RB-02 | Base 所有者 | 逐条停用清单内的临时自动化/节点，不删除配置和运行记录 | 失败运行、错误码、节点实际 envelope | 每个临时资源的停用证据 | 清单外资源不得操作 |
| T2-RB-03 | 执行人 | 对受影响业务对象执行工作流专属回退；状态只回到获批的已有状态 | 原始证据、SLA、人工确认、错误审计 | 对象前后状态对照 | 不知道合法目标状态时保持原状态 |
| T2-RB-04 | 执行人 + 复验人 | 以精确主键列出待清理的 `SYN-PERMISSION-TEST` 记录和临时视图/文档/会话；先计数复核 | 正式记录、正式证据、AI 审计 | 待清理清单、数量、主键、资源所有者 | 不得使用模糊文本或通配选择 |
| T2-RB-05 | Base 所有者 | 仅清理复验通过的临时记录；优先归档/标记失效，只有赛事规则要求且无引用时才删除 | 正式证据、失败审计、回退清单 | 清理前后计数与剩余引用检查 | 有正式引用或归属不清即不删除 |
| T2-RB-06 | 参赛者本人 / 管理员 | 撤销临时分享、临时协作者、OAuth 授权、测试凭证和管理员临时许可；必要时轮换凭证 | 授权审批记录的脱敏摘要 | 撤权/轮换时间、主体、范围 | 协作者不得代持或展示凭证 |
| T2-RB-07 | 另一复验人 | 复验正式业务状态、SLA 起点、证据、权限边界和 P01/P03 独立结果未被破坏 | 所有正式证据 | 回退回执与遗留待办 | 任一异常即冻结现场并报主控 |

通常顺序为 00→01→02→03→04→05→06→07。若发生 token、OAuth、webhook 或凭证泄露，安全分支改为：本人立即撤销/轮换凭证 → 管理员收回应用/资源授权 → 再执行 00—07 的其余步骤。泄露值不得进入证据截图或本仓库。

## 3. 失败快照模板

回退前在受控证据副本中填写；仓库只登记脱敏索引。

| 字段 | 填写规则 |
| --- | --- |
| 回退编号 | `T2-RB-{范围}-{序号}` |
| 发生时间 | 带时区；不得用文件创建时间代替 |
| 执行人 / 平台账号角色 | 本人、所有者、管理员、普通协作者、无特权账号或未登录；不记录账号标识 |
| 逻辑业务角色 | 单独填写或“不适用”；不能当平台权限角色 |
| 对象引用 | 使用脱敏逻辑 key/证据索引，不写完整 URL 或真实资源 ID |
| 前状态 / 当前状态 | 使用冻结的五组状态值；未知写“待核验” |
| `sla_started_at` | 原样保留；回退、重派和自动化失败均不得重置 |
| 幂等键 / 输入哈希 | 只保存必要的脱敏哈希或受控索引 |
| AI 节点、模式、版本、重试数 | 只记录真实发生的运行；没有运行不得补造 `ai_audit` |
| 错误分类 | 使用 F01—F12 和平台实际错误摘要 |
| 正式证据引用 | 只读，不在回退中删除 |
| 临时资源清单 | 必须逐项列 key、类型、所有者、用途和清理决定 |
| 复验人 / 复验时间 | 关键权限、SLA 和正式证据由另一人复验 |

## 4. 六工作流专属回退

### W1 接入幂等

- 停点：同一幂等键内容冲突、授权范围缺失、原文写入异常或部分创建。
- 保留：原始反馈原文、`idempotency_key`、`authorization_scope`、原记录 ID、输入哈希和冲突日志。
- 回退：不覆盖旧记录；新建的部分临时记录标记为待人工核验。只有它同时带 `SYN-PERMISSION-TEST`、在 T2-RB-04 精确清单中且无任何引用时，才进入 T2-RB-05。
- 禁止：删旧记录后重试、换一个幂等键掩盖冲突、用宽权限重放。

### W2 风险分诊

- 停点：N1/N2/N3 envelope 校验失败；同版本一次修正后仍失败；硬规则与 AI 建议冲突。
- 保留：反馈原文、硬规则结果、每次真实 envelope、`retry_count`、原 `processing_status` 和现场如有的案件引用。
- 回退：停止节点链并转人工；不得降低硬规则风险。没有真实 AI 尝试时只写人工降级证据，不伪造 `needs_human` 审计记录。
- 禁止：把自由文本输出标成结构通过、删除失败 envelope、继续执行 W6/W3。

### W6 同事件阶段

- 停点：重复候选证据不足、同/跨事件模式混用、自动并案企图。
- 保留：两条原案件、候选相似度/证据、N5 实际 envelope 和人工决定。
- 回退：默认保持案件分开；撤销尚未确认的临时关联。不得减少正式案件数或把跨事件案件合成一案。

### W3 关联派单

- 停点：实体证据弱、标识缺失、正式实体或责任/SLA 版本未经人工确认、工单部分创建。
- 保留：N4/N6 候选、证据、缺失字段、原案件状态、`sla_started_at`、人工确认记录和工单草稿审计。
- 回退：保持候选而非正式关系；案件进入获批的“待补充”路径或保持原状态；未满足关口的工单不得变成“待接单/处理中”。
- 禁止：发明车辆/任务/站点 ID、自动确认责任、重置 SLA。

### W4 SLA 协同

- 停点：提醒、升级、接管或状态写入失败；通知目标越权或泄露字段。
- 保留：失败前案件/工单状态、`sla_started_at`、`sla_due_at`、提醒/升级历史、接管记录和错误日志。
- 回退：只停用失败的临时自动化，业务状态保持原值；通过已经验证的人工值守路径通知。保底未验证时只登记待办。
- 禁止：通过重派、复制工单或改时间掩盖超时；删除升级记录。

### W5 解决验证与回访

- 停点：证据不足、N7 schema 失败、回复未审、回访异常或结案人未授权。
- 保留：处置证据、草稿、引用、人工审核、回访结果、原案件状态和 SLA 历史。
- 回退：草稿保持未发布；案件回到获批的“处理中”路径或保持原状态；不得写 `closed_at` 或宣称结案。
- 禁止：自动对外回复、自动赔偿/恢复时间承诺、删除异常回访。

### W6 跨事件、改进与观察阶段

- 停点：模式错用、问题簇未经审核、根因假设被当作最终根因、未审知识发布、观察时钟/分母缺失。
- 保留：案件、问题簇、支持与反证、复发记录、clock source、N5/N6/N7 实际 envelope、改进项目原状态和人工决定。
- 回退：问题簇保持候选/待审核，知识保持草稿，改进保持原状态；没有业务量分母只保留复发案件数。
- 禁止：自动最终根因、自动知识发布、删除反证、把合成观察写成企业成效。

## 5. 临时自动化与节点停用

1. 在本地隔离映射中找到明确的 `automation_id`/节点槽位；仓库 example 仍为 `null`。
2. 在飞书页面确认名称、所有者、创建时间和 `SYN-PERMISSION-TEST` 用途；将清单交复验人。
3. 先关闭触发开关，再等待/确认在途运行停止；记录最后一次运行索引。
4. 不删除运行历史，不重命名成正式自动化，不把失败节点移到另一条正式链。
5. 复验没有新的测试记录或提醒产生，正式自动化状态没有变化。
6. 删除临时配置仅在赛事规则要求、资源无引用且证据已另行保留时由所有者决定；默认保留停用状态以便审计。

## 6. 临时授权撤销

### 文档/Base 分享

- 由参赛者本人撤销临时匿名外链、临时协作者和测试账号；先截图当前范围并记录受影响资源。
- P01 与 P03 分别复验；撤掉 Base 测试账号不能代替撤掉匿名文档外链。
- 若出现越权泄露，先停止分享，再保存脱敏错误证据；不得通过给测试账号管理员权限来“验证可访问”。

### 审批、机器人、知识库、妙搭、Aily

- 由资源所有者移除测试审批人、测试会话/机器人、临时知识权限、妙搭数据源授权和 Aily 工具权限。
- 只撤销本轮临时授权；正式审批、群、知识空间或应用不在清理范围。
- 这些能力的撤销或失败均不改变 Base 核心契约，也不把对应 P 项自动改为“不可用”。

### 自建应用、OpenAPI、OAuth 与 `lark-cli`

- 只有参赛者本人能创建、撤销或轮换凭证；管理员负责撤销应用权限和资源协作者关系。
- 先撤销短期 token/OAuth 会话，再撤资源权限，最后确认本机 credential store 没有测试登录；任何命令输出只保留脱敏摘要。
- 不在仓库、聊天、截图或回退清单中粘贴 token、secret、设备码、授权 URL、完整资源 URL。
- R2 未执行任何上述操作；本节只是未来现场步骤。

## 7. `SYN-PERMISSION-TEST` 记录清理

### 7.1 进入条件

同时满足才可进入 T2-RB-05：

1. 自动化和节点已停用，确认不会继续产生记录。
2. 记录标题/测试标记精确包含 `SYN-PERMISSION-TEST`，且 `data_scope=synthetic_experiment`。
3. 记录主键逐条列入 T2-RB-04 清单；执行人和复验人确认数量。
4. 记录不被正式证据、演示故事、关系字段、AI 审计或回退记录引用。
5. 清理方式、执行时间和执行人已预先写入回退清单。

只满足 `data_scope=synthetic_experiment` 不足以删除，因为 canonical 演示集也属于合成数据；必须同时满足测试标记、精确主键清单和无正式引用。

### 7.2 清理顺序

1. 先清理临时关联，确认不会级联影响另一端；不得删除另一端正式记录。
2. 按依赖逆序处理临时改进、问题簇、工单、案件和原始反馈；车辆、任务、责任矩阵、知识索引与 AI 审计默认不删除。
3. 优先使用“归档/标记失效”并隐藏于业务视图。只有平台没有安全归档方式、赛事规则要求清空、且无引用时才逐条删除清单内临时记录。
4. 删除前后分别记录数量和主键摘要；不使用“全选”“清空表”“按模糊前缀批量删除”或 OpenAPI 通配脚本。
5. AI 审计与自动化运行日志属于正式证据链，不因业务测试记录清理而删除；对已清理对象保留脱敏 object_ref。

### 7.3 禁止清理的内容

- 原始反馈原文和用于证明幂等冲突的旧记录。
- 任何正式证据截图、运行记录、审批/人工确认或复验回执。
- `sla_started_at`、升级/接管历史、失败前状态和异常通知记录。
- AI 实际 envelope、schema 校验错误、一次重试和人工修改记录。
- 支持证据、反证、根因审核、知识发布审核和回访异常。
- 资源归属不明确或不在 T2-RB-04 精确清单中的任何对象。

## 8. 回退复验与交接

另一复验人按以下清单完成 T2-RB-07：

- 正式对象的主键、状态和关系数量与失败前快照一致，或差异有授权人工决定。
- 所有受影响案件/工单 `sla_started_at` 未变化，`sla_reset_count` 没有因回退增加。
- 正式证据、AI 审计、自动化运行日志和人工关口记录仍可访问。
- 临时自动化不再触发；正式自动化没有被停用。
- 临时分享/OAuth/权限已按清单撤销；没有通过宽权限账号保留绕过。
- `SYN-PERMISSION-TEST` 只按精确清单清理；无正式引用断裂。
- P01—P13 状态只按真实复验结果更新；未完成项仍为“未测试”。
- 遗留限制、管理员待办和下一次复验条件已写入证据模板。

任何一项未通过时，保持现场冻结并报主控；不得为了收尾把限制改写成通过。
